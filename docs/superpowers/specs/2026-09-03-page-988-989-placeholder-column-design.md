# Page 988/989 短横线占位符伪列修复设计

## 问题与根因

`fix/zh_all_table_pages.pdf` 的第 988、989 页均为中文无线表格。正确结构是一个项目列加六组双叶子金额列，共 13 列；当前 native-span 恢复结果为 18 列，额外的 5 列位于相邻公司组之间并且整列为空。

列带推断会根据 atom 的水平重叠建立连通组件。短横线 `-` 是金额空值占位符，宽度仅为 2.064 至 3.764pt，并与同一金额列中的数值右端完全重叠。当前占位符与数值的兼容条件同时要求覆盖占位符宽度的 75% 且绝对重叠不少于 4pt。窄短横线即使 100% 重叠也无法达到 4pt，因此重复短横线形成独立窄列带。

后续叶子列细化保留该窄带，并把六个公司宽带分别拆成两个金额列，最终得到 `1 + 6 * 2 + 5 = 18` 列。列分配发生重叠平局时，短横线落入靠前的正常金额列，窄带没有内容；空槽物化再为该窄带的每一行生成独立空 Cell，所以 PNG 中短横线位于正常金额列而空列位于其右侧。

## 方案

占位符与数值的列带兼容判断只采用占位符覆盖比例：实际水平重叠至少覆盖占位符 bbox 宽度的 75%。移除固定 4pt 下限，不改变普通 atom 之间的兼容条件，也不增加新的清理阶段。

选择该方案的原因：

- Page 988/989 的目标短横线覆盖比例为 100%，应与金额组件连通。
- Page 944 的既有误合并反例仅由尾部空白与相邻数值擦碰，覆盖比例约为 45.6%，仍会被拒绝。
- 修复发生在错误列带的来源位置；不删除最终空列，也不改变空槽物化不变量。

## 调用位置与约束

修改位置为 `wireless_structure/columns.py::_compatible()`，由 `infer_column_bands()` 在构建水平重叠组件时调用。

整个流程继续只消费 native span、atom、列带、物理 Cell 和逻辑 Cell。不得调用 `page.get_text("words")`，不得回退到 `extract_zebra()` 或 legacy 文本重建路径。逻辑网格仍须覆盖所有槽位，空槽仍物化为独立 `1x1` Cell，occupancy conflict 检查保持不变。

## 测试与页面验证

先增加最小失败测试：宽度小于 4pt 的短横线与金额数值 100% 水平重叠时，二者必须属于同一列带。保留 Page 944 的 45.6% 擦碰反例，证明比例阈值仍拒绝跨列误合并。

实现后验证：

- 相关列带和 Page 944 测试全部通过。
- 第 944 页仍恢复为 13 列且无占位冲突。
- 第 988、989 页分别恢复为 13 列，不存在整列为空，表头双叶子跨度保持正确。
- 页面级结果写入新的独立输出目录，并核对结构化结果和最终 PNG。
