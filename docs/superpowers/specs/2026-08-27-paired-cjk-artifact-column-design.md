# 成对中文单字伪列修复设计

## 目标

修复 native-span 无线表格将居中双字标签的第二个字误判为独立叶子列的问题。第 188 页下方管理费用表应从 `10x4` 恢复为 `10x3`，表头“项目”和末行“合计”各自属于项目列中的一个单元格。

## 根因

当前列带只要求至少两个 atom、两个 y 层级。第 188 页的 `目` 和 `计` 位于相同 x 轨道，形成 `support=2 / y_support=2` 的窄列；但二者分别是 `项/目`、`合/计` 的第二个原生字符。该窄列没有正文内容，不能作为独立列证据。

列带一旦建立，`项/合` 和 `目/计` 会被分配到不同槽位；后续同槽位合并按设计不能跨越该边界，因此无法恢复“项目/合计”。

## 设计

在初始列带推断完成后、表头拓扑细化前，执行一次窄列伪影过滤。

一个列带只有同时满足以下条件才删除：

- 支持 atom 数为 2 至 3，且至少位于两个不同 y 层级。
- 所有支持 atom 都是单个 CJK 字符。
- 每个支持 atom 都有一个左侧单 CJK atom：两者 source block/line 相同、flow 连续、y 中心对齐，正间距不超过 `2.1 * min_font_size`。
- 所有左侧配对字符都属于同一个相邻左列带。
- 左列带至少有 4 个 atom、3 个 y 层级，并且 support 至少为伪列的两倍。
- 伪列中不存在数字、多字符正文或非配对内容。

删除后重新编号列带。第二字符会按最近列带重新分配到左侧项目列，现有 `merge_same_slot_fragments()` 再依据同 source line、连续 flow 和单 CJK 规则合并，无需“项目/合计”关键词特例。

## 保守边界

- 真实窄列只要包含数值、多字符内容、超过 3 个支持 atom，或缺少逐项左字符配对，就保留。
- 不在 grid 建成后删除空列，不给特定文字设置 colspan。
- 不修改英文、有线表格或 page words 路径。

## 验证

- 列带单元测试复现 `项/目`、`合/计` 和稳定正文/金额轨道，确认四列降为三列。
- 反例测试确认具有真实正文值的单字窄列不会删除。
- 合并测试确认过滤后“项目/合计”分别成为单个同槽位 cell。
- 重跑第 188 页，确认三表结构从上到下为 `3x5`、`8x3`、`10x3`；下表 cell 数为 30，所有槽位无缺失冲突，PNG 中不再有竖线穿过“项目/合计”。
