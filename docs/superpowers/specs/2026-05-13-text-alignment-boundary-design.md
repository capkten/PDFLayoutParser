# 文本对齐表格边界修正设计

## 背景

当前表格提取主要有两条分支，均位于 `src/pdflayoutparser/table_extractor.py`：

- `line_projection`：处理有明确线框的表格
- `text_alignment`：处理无线框或弱线框、主要依赖文本对齐的表格

这次排查出来的 `page-034.json`、`page-045.json`、`page-046.json` 问题，根因都不在线框链路，而在 `text_alignment` 分支。

目前暴露出来的现象是同一类问题的不同表现：

- 真实表格前后的非表格说明文字被吸进表格区域
- 含日期、金额、编号的正文段落被误判成表格
- 一个很短的表头 span 被和表体切开，最终没有进入表格
- 表体被识别出来了，但附近标题行或说明行也被一起并进表格

这些问题本质上都是文本对齐链路里的“边界控制失败”，不是线条识别或单元格几何重建失败。

## 目标

- 降低正文类 span 因重复数字碎片而被误判成表格的概率
- 对通过初筛的文本表格候选做真实结构区间裁剪
- 将紧邻表体、结构上属于表格的短表头 span 合并回去
- 保持现有线框表格提取行为不变

## 非目标

- 不重写线框表格提取链路
- 不修改 JSON 或 Markdown 的输出 schema
- 不为当前这一个 PDF 写特判规则
- 不处理 OCR 图片表格

## 根因总结

### 1. 候选接受条件过粗

`_collect_text_candidate_regions()` 当前的逻辑是：只要一个 span 同时满足以下条件，就把整个 span 当成表格候选：

- `_infer_column_guides()` 找到至少两个 guide
- `_has_repeated_column_structure()` 返回 true
- `_looks_like_paragraph_region()` 没有把它排除掉

这套条件对“长正文里夹杂日期、金额、文号”的情况过于宽松。

### 2. span 切分只看纵向间距

`_split_rows_into_spans()` 只使用垂直 gap 来切分，不判断“表格结构到底从哪一行开始、在哪一行结束”。因此会出现：

- 表格前面的说明段仍然和表格处于同一个 span
- 表头和表体被切成两个 span

### 3. span 通过后没有再做裁边

一个 span 一旦通过候选判断，就会整个变成表格区域。当前没有第二层逻辑去保留“真正持续符合列结构的连续子区间”。

### 4. 缺少表头回并机制

如果一个很短的表头 span 自身达不到重复结构门槛，但它下面紧接着的表体 span 通过了候选判断，当前逻辑会直接丢掉这个表头，而不是把它并回去。

## 总体方案

保留现有 `text_alignment` 分支，但把它拆成三段明确的决策流程：

1. 候选发现
2. 结构区间裁剪
3. 表头样式 span 回并

这样改动可以限制在 `table_extractor.py` 内部，不需要重写整条链路，同时能覆盖这次确认的几个典型问题。

## 详细设计

### 第一阶段：加强候选发现

目标是更早排除“带零散数字锚点的正文 span”，不要让它们进入后面的建表流程。

#### 调整点

- 保留 `_split_rows_into_spans()` 作为第一层粗分段
- 强化 `_looks_like_paragraph_region()`
- 强化 `_has_repeated_column_structure()`
- 在 span 被接受前，增加一层按行打分的结构判断

#### 新增辅助函数

- `_score_row_against_guides(row: dict, guides: list[float]) -> dict`

这个函数负责计算单行的结构特征，例如：

- 命中了多少个不同 guide
- 这些命中是否分布在两个及以上分离的列区间
- 这一行是否本质上是一个长正文 token 加一两个数字碎片
- 这一行是否被大段全宽文本主导

#### 新的接受规则

span 不应仅仅因为“存在重复 guide”就被接受，还应额外要求：

- 有足够多的 supporting rows 体现出真正的多列结构
- 对于多列表格，至少有一部分行命中 3 列及以上
- 如果绝大部分行都是全宽正文，只有极少数行贡献了数字锚点，则应拒绝

这一步主要针对 `page-045.json` 的误判。那一页的正文里，`2022`、`年1`、`月1`、`15`、文号等重复出现，伪造出了“像列一样稳定”的锚点。

### 第二阶段：对通过候选的 span 做真实结构区间裁剪

一个 span 即使被接受为候选，也不能立即整体输出为表格，必须先裁剪出其中真正连续符合列结构的行区间。

#### 新增辅助函数

- `_trim_span_to_structured_rows(rows: list[dict], guides: list[float]) -> list[dict]`

这个函数负责：

- 按 guide 对每一行打分
- 将行分类为 `structured`、`weak`、`prose`
- 保留以 `structured` 为主的最长连续区间
- 允许区间内部存在少量 `weak` 行
- 去掉 prose 风格的前缀和后缀

#### 预期效果

- `page-034.json`：保留真实表格，但裁掉前面的说明文字
- `page-046.json` 的第二个表：把上面的标题或说明行排除掉
- `page-045.json`：如果整段并不存在稳定结构区间，则该候选直接消失

### 第三阶段：把表头样式 span 合并回后续表体

对“单独成段、但显然属于下方表格的短表头 span”增加恢复机制。

#### 新增辅助函数

- `_merge_header_like_span(previous_rows: list[dict], body_rows: list[dict], body_guides: list[float]) -> list[dict]`

#### 合并条件

当前一个 span 满足以下条件时，可以把它并入后一个结构化表体：

- 前一个 span 很短
- 与后一个表体的垂直间距很小
- 与后一个表体有很强的水平重合
- 其中至少一部分 token 能和表体 guides 对齐
- 它本身又不够像普通正文段落

#### 预期效果

- `page-046.json` 的第一个表：把缺失的表头并回表格区域

## 文件影响范围

主要修改文件：

- `src/pdflayoutparser/table_extractor.py`

主要测试文件：

- `tests/test_table_extractor.py`

本次预期不修改：

- `src/pdflayoutparser/layout_builder.py`
- `src/pdflayoutparser/json_writer.py`
- `src/pdflayoutparser/markdown_writer.py`

## 推荐的内部重构边界

为了保证后续可排查，不建议继续把更多阈值判断直接堆进 `_extract_via_text_alignment()`。建议围绕几个明确的辅助函数展开：

- `_score_row_against_guides(...)`
- `_is_textual_false_positive_span(...)`
- `_trim_span_to_structured_rows(...)`
- `_merge_header_like_span(...)`

这样后续调试时可以直接按失败阶段定位：

- 候选误入
- 裁边失败
- 表头与表体断开

## 测试策略

在 `tests/test_table_extractor.py` 中补充回归测试，优先使用动态构造的 PDF。

### 必须覆盖的场景

1. 含重复数字碎片的正文不会被识别为表格
2. 真实文本表格前面有说明段时，说明段会被裁掉
3. 紧邻表体上方的短表头 span 会被合并回表格
4. 表体上方的标题行或说明行，如果不满足真实列结构，则不会被吸进表格

### 用例构造建议

优先构造小而单一的 synthetic PDF，用来隔离结构问题：

- 含 `年/月/日/金额` 重复模式的正文段
- 一个上方有短表头、下方是规则表体的文本表格
- 一个说明段后面紧跟真实文本表格的页面

生产 PDF 可以继续用于人工验证，但自动化测试应尽量保持最小、可复现、可读。

## 风险

### 风险 1：候选收紧过头

如果第一阶段规则过严，真实但较稀疏的文本表格可能被漏掉。

缓解方式：

- 对大 span 采用更强结构要求
- 对小而紧凑的候选保留适度宽松空间

### 风险 2：裁边过头

如果第二阶段过于激进，表格内部本应保留的弱表头行或说明行可能被误删。

缓解方式：

- 允许结构区间内部存在少量 `weak` 行
- 在裁边后再执行表头回并

### 风险 3：表头回并把正文拉回来

如果第三阶段条件太松，附近普通段落可能被当成表头并回表格。

缓解方式：

- 要求强水平重合
- 要求极小垂直间距
- 要求至少部分 guide 对齐
- 仅允许短 span 参与回并

## 验收标准

满足以下条件时，认为这次修改完成：

- `page-034.json` 仍保留真实表格，但不再包含前缀非表格说明行
- `page-045.json` 不再输出误判的 `text_alignment` 表格
- `page-046.json` 的第一个表包含原先缺失的表头
- `page-046.json` 的第二个表不再吸入非表格行
- 现有线框表格相关测试不发生回归

## 推荐实施顺序

1. 先加强候选接受条件，补按行结构打分
2. 再加入通过候选后的结构区间裁剪
3. 最后加入表头样式 span 回并
4. 补齐四类 synthetic 回归测试

这样可以先压掉最明显的纯误判，再修真实表格的边界质量问题。
