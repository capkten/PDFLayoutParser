# 有线表格开放边界单元格恢复设计

## 目标

修复有线表格的物理外边界在 PDF 中只绘制了一部分时，解析器因 flood-fill 将边界内区域判为“表格外”而丢失逻辑 Cell 和原始文本的问题。

目标输出是完整的逻辑网格：有文字的槽位保留原始文字，确实没有文字的槽位生成 `text=""` 的独立 Cell，合并表头使用正确的 `rowspan/colspan` 表达。

## 已确认的根因

当前调用链位于 `src/hexai_pdf_parser/tables/extractors/wired_table_extractor.py`：

1. `_extract_lines_from_drawings()` 提取 PDF 的水平线和垂直线。
2. `_find_table_regions()` 按线段相交关系得到有线表格区域。
3. `_build_cells_for_region()` 根据网格坐标生成边界，并从缺失边界向外做 flood-fill。
4. `_assign_text_to_line_cells()` 只向已经生成的 Cell 绑定页面文字。

因此，若最底横线没有延伸到最右列，或最右竖线没有贯穿表头，Cell 会在第 3 步被删除；即使 PDF 中对应区域有 `903,152.90`、`9,656.85`、`---` 或表头文字，第 4 步也没有目标 Cell 可以接收文本。

## 推荐方案

在 `_build_cells_for_region()` 的 flood-fill 之前增加“外边界连续性恢复”，只恢复表格区域的四条外边界，不改变内部缺线的合并语义。

### 判定条件

- 只处理与 `bbox.x0`、`bbox.x1`、`bbox.y0` 或 `bbox.y1` 对齐的外边界；内部竖线或横线缺失仍表示可能存在 `colspan` 或 `rowspan`，不能直接补成分隔线。
- 先使用已经 snap 后的 `h_ys`、`v_xs` 作为逻辑网格坐标。
- 外边界已有部分线段时，只有在同一线网中存在足够的连续网格证据时，才把该线段延伸到完整区域边界：
  - 水平外边界：同一表格至少有两条其他水平网格线覆盖完整宽度，且当前外边界线段至少覆盖一个完整网格列，端点与已有网格列边界对齐。
  - 垂直外边界：同一表格至少有两条其他水平网格线覆盖完整宽度，且当前外边界线段至少覆盖一个完整网格行，端点与已有网格行边界对齐。使用正交的完整横线作为证据，可以处理合并表头中内部竖线按设计缺失的情况。
- 外边界完全没有线段时，保留现有“由区域边界合成外框”的行为；此次只补充“部分线段”场景。
- 不根据页码、公司名称、金额或其他业务文字硬编码，不把普通内部缺线改成外边界。

### 数据流

恢复后的外边界进入现有 `h_edges`/`v_edges` 计算。这样 flood-fill 不会越过已确认属于表格的缺线区，所有逻辑槽位先生成，再由现有文本绑定流程按 bbox 归属原始文字。后续 Cell 合并、幽灵边行清理和单列伪表格过滤保持不变。

## 测试方案

先在 `tests/test_wired_table_extractor.py` 增加失败测试：

1. 部分底部外边界的右下角槽位仍生成，并可绑定位于该槽位中的文字。
2. 部分右侧外边界的多级表头恢复，内部缺线仍形成合并 Cell，而不是被拆成错误分隔列。
3. 开放边界内没有文字时仍生成空 Cell，不能只恢复文字覆盖的槽位。
4. 既有完整闭合表格、部分内部线段合并、单 Cell 伪表格过滤测试继续通过。

页面级验证使用输入 `fix/zh_all_table_pages.pdf` 的新输出目录，逐页核对四个目标表格的行列数、Cell 文本、跨度、占位冲突和原始 PNG；之后再进行全量 E2E 和独立标签比较。

## 非目标

- 不修改无线表格 native-span 结构恢复路径。
- 不修改黄金标签，不把旧标签自动当作新的真实文本依据。
- 不取消有线表格的外部区域过滤，也不通过全局保留所有开放区域来规避问题。
