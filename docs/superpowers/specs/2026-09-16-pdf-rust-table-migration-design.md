# PDF 表格逻辑 Rust 渐进迁移设计

状态：已确认（2026-09-16）

Python 行为基线：`feature-dev@dc00211fe0cf95bc8c3412c883311fe86f8d8357`

实现分支：`codex/pdf-fast-rust-migration`

## 决策摘要

将有线、英文无线、中文/混合无线表格的计算逻辑逐函数迁移到 Rust。Python/PyMuPDF 继续负责 PDF 打开、页面内容提取、语言分流、模型调用和现有公开接口；Rust 只接收普通的、自有所有权的数据结构，不接触 `fitz.Page` 或 PDF 对象。

本次不做独立 microbenchmark。迁移验收以函数级输入输出等价、现有 Python API/JSON 输出不变，以及现有 `fix` 端到端测试通过为准。

## 目标与非目标

目标：

- 保持当前 Python 行为作为兼容基线，迁移期间不顺带修算法问题或改变表格策略。
- 以单个算法函数为单位翻译并验证；Rust 内部函数与原 Python 职责保持清晰对应。
- 保持现有 Python 调用签名、表格对象、序列化结构和错误/空结果语义。
- 让 Rust 的长时间计算在不回调 Python 的阶段释放 GIL。

非目标：

- Rust 重新实现 PDF 解析、渲染或 MuPDF/PyMuPDF 能力。
- 同时迁移 ML 检测、页面语言识别、页面渲染、调试图输出或服务层编排。
- 本阶段新增性能门槛、独立 microbenchmark 或算法行为优化。

## 兼容性约束

比较对象是最新已提交的 `feature-dev` 行为，而不是较早的 profiling 分支。特别保留：

- 有线表格的绘图过滤、裁剪与图表区域排除行为，包括 page 415 对应的修正。
- 中文/混合页面的 native-span 路径，包括白名单单字间隔合并行为。
- 表格与单元格的顺序、`source`、置信度、bbox、文本、行列索引、`rowspan`、`colspan` 和空槽位。
- 当前异常处理、空结果和 Python 外部 JSON 表示。

函数级结果按当前计算和序列化语义精确比较，不通过放宽浮点容差来掩盖差异。出现差异时，Rust 实现应复现 Python 的舍入、排序和边界规则。

中文/混合无线表格还必须保持项目现有约束：span 到 atom 阶段完成文本组合；结构恢复只消费 native span 派生数据；不得回读 `page.get_text("words")` 或回退到 legacy/zebra 重建；跨度调整后检查 occupancy；空槽位按网格独立物化。

## 架构与数据边界

```text
PDF / fitz.Page
        |
        v
Python 提取器：按算法路径提取所需页面数据
        |
        v
Owned DTO -> PyO3 批量调用 -> Rust 算法函数
                                      |
                                      v
                               结果 DTO
                                      |
                                      v
Python 适配回 Table / Cell -> 当前序列化输出
```

### Python 负责

- 打开 PDF，访问 `fitz.Page` 和 PyMuPDF/MuPDF API。
- 按调用路径提取并规范化数据，转换为普通数值、字符串、列表和结构化 DTO。
- 保留语言路由、ML 检测、页面/服务编排、公开方法签名和 `Table`/`Cell` 构造。
- 将 Rust 结果适配回项目现有对象；把错误映射为当前调用路径既有的异常或空结果行为。

### Rust 负责

- 有线：消费已提取的绘图线段/矩形、裁剪与样式信息、页面几何、字符区域及文字框，执行线条合并、区域拓扑、单元格构造和文字归属等纯算法。
- 英文无线：消费背景区域、文字块/文字框和页面几何，执行斑马纹分组及文本对齐结构恢复。
- 中文/混合无线：消费 native span、字符框、字体/字号、遍历顺序和来源位置，执行 span/atom、列带、物理行、逻辑网格、跨度与空槽恢复。
- 使用有类型的输入/输出结构；Rust 不保留 Python 对象，不在计算中回调 Python。

PyO3 边界按页或表格区域批量传递数据，避免每个辅助函数单独跨 FFI。算法仍按函数粒度翻译和单测。扩展使用 PyO3 与 maturin；按项目最低 Python 版本选择 abi3 下限，wheel 仍按操作系统、架构及 native 运行环境分别构建。

## 迁移顺序

1. 建立 Rust 扩展构建和 Python 适配层，定义最小 DTO，并验证现有调用方/API 不变。
2. 从有线表格纯几何/线网函数开始逐个迁移，再接入文字归属和区域级表格恢复。
3. 迁移中文/混合 native-span 结构恢复，严格保留 span 来源连续性、逻辑网格 occupancy 和空槽约束。
4. 迁移英文无线斑马纹与文本对齐逻辑，保持现有语言分流和优先级。
5. 每条完整路径通过等价验收后，将对应 Python facade 切换到 Rust；其余尚未迁移路径继续由 Python 执行。

此顺序按算法边界分批，不表示某一路径可以降低等价要求。Python 旧实现仅在对应函数迁移期间用于结果对照；通过端到端验收后，移除不再使用的生产实现，保留必要的测试向量和公开兼容 facade。

## 验证策略

- 每个被迁移函数先有明确的输入/输出用例，覆盖正常、边界、空输入和当前可观察的失败/回退行为。
- Rust 纯算法运行 `cargo test`；Python 数据提取、DTO 转换、PyO3 调用和对象适配运行 pytest。
- 迁移期间对同一输入分别运行旧 Python 函数和 Rust 函数，精确比较结果；差异未解释并修复前不切换该函数的生产路由。
- 每完成一条有线/无线路径，运行项目 `fix` 端到端测试，并核对结构化结果和页面 PNG：表格数量、来源、行列、单元格文字/跨度、bbox、空槽位及边界。
- 不以运行时间作为本阶段的通过条件，不报告未经独立测量的性能收益。

## 分支与测试数据

迁移分支从已提交的 `feature-dev@dc00211` 建立，以包含最新已提交的有线及中文无线修正。原 `codex/pdf-fast-profiling` 分支保持不变。主工作区当前的未提交/未跟踪文件不合并、不清理；本机 `fix/zh_all_table_pages.pdf` 测试输入留在原处，端测通过显式路径使用，不复制进 Git。

## 风险与控制

- **输入快照遗漏字段：** 先按调用链逐函数盘点页面访问，再为每个函数建立 DTO 和输入输出测试；只提取该路径实际需要的数据。
- **Python/Rust 数值或排序差异：** 用精确测试固定边界、排序和舍入语义；不以宽容差放行。
- **功能拆分破坏现有 monkeypatch/API：** Python facade 和调用签名保留，现有路由及兼容测试纳入 pytest。
- **某一路径暂未迁移完成：** 只切换已通过函数/路径，其他路径继续使用 Python，不做全量一次性替换。
