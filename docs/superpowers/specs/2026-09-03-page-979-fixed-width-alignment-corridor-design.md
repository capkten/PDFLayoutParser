# Page 979 等宽文本列对齐走廊否决设计

## 背景与根因

`fix/zh_all_table_pages.pdf` 页索引 `979` 包含一张视觉上为 8 个叶子列的中文无线表格。页面只有表格顶线、表头下线和底线，没有竖线或正文行线，因此最终结构依赖 native span 到 atom 的字段边界恢复。

模型已正确检出完整表格区域 `[71.5, 90.9, 519.0, 756.6]`，置信度为 `0.9807`。失败发生在 `src/hexai_pdf_parser/tables/wireless_structure/text_runs.py` 的 `build_text_runs()`：注册资本金额与下一列主要经营地处于同一 native line，金额 span 还包含尾随空格，导致 `1,000.00` 与 `深圳` 的 bbox 间距为 `3.232pt`，小于 mixed CJK/Western 合并上限 `3.696pt`。现有 `_can_join()` 因此允许合并，形成 `1,000.00深圳` 等 `same_line` atom。

现有 `_has_alignment_corridor_veto()` 实际找到 21 行稳定见证：金额统一右对齐，地点统一左对齐，共同空白走廊宽 `3.232pt`，大于对齐容差 `1.267pt`。但其保护条件要求左右两侧的非对齐边缘都发生变化。金额长度不同，左侧通过；地点均为同字体双字城市名，`x0/x1` 跨行完全不变，右侧失败。否决未触发后，两列证据在 atom 阶段丢失，列带只恢复为 7 列；表头“注册资本”和“主要经\n营地”同时进入 `R2C2`，产生 `R2C2 conflict: T2/T3`，最终 occupancy 检查拒绝整表。

## 目标与非目标

目标是在 span 到 atom 的组合阶段扩展现有对齐走廊否决，使具有稳定锚点、重复空白通道和多样文本值的等宽字段仍可证明为独立列。否决发生时，左右 span 从一开始进入不同 group，后续不做拆分或补救。

本次不修改通用间距阈值，不增加 numeric-to-CJK 全局禁并规则，不在列带、物理网格或 occupancy conflict 阶段反推字段边界，不依赖“深圳”“注册资本”等业务文字，也不进入 `extract_zebra()`、legacy `_rebuild_text_aligned_table()` 或 page words 二次重建。

## 方案比较

### 方案一：扩展对齐走廊的等宽侧证据，采用

保留现有稳定锚点、至少 3 行见证和共同空白走廊条件。对于某一侧非对齐边缘不变化的情况，允许“该侧跨行出现至少 3 个不同的非空规范化文本值”替代边缘变化证据。至少另一侧仍必须满足现有非对齐边缘变化条件。

该方案直接修复现有几何否决的盲区，保持 veto-only 语义，且能用内容多样性区分独立地点列和固定单位后缀。

### 方案二：使用可见字符 bbox 计算间距，不采用

排除金额 span 尾随空格后，本页实际字形间距约为 `5.52pt`，可直接超过合并阈值。但这会改变所有带空格的同字段碎片间距，可能破坏正常短语组合，影响面过大。

### 方案三：禁止 numeric-to-CJK 合并，不采用

该方案简单，但会误伤 `100万元`、`30天` 等合法字段，缺少重复结构证据，不符合保守恢复原则。

## 核心判定

`_has_alignment_corridor_veto()` 继续只在 `_can_join()` 已允许合并后执行。对每组候选对齐模式，必须同时满足：

1. 当前左右 span 位于同一视觉行，现有来源连续性和间距条件允许合并。
2. 当前行加至少两个其他视觉行，共计至少 3 行，能唯一匹配同一组左右对齐锚点。
3. 左右锚点的跨行 spread 均不超过既有 `support_tolerance`。
4. 所有支持行的共同空白走廊宽度大于 `support_tolerance`。
5. 至少一侧的非对齐边缘 spread 大于 `support_tolerance`。
6. 另一侧满足以下任一条件：非对齐边缘同样发生变化；或者支持行中存在至少 3 个不同的非空规范化文本值。

只有全部条件成立时返回 `True`，在 `build_text_runs()` 中阻止 `groups[-1].append(span)`。内容多样性只有 veto 权，不能主动合并、拆分或创建列带。

文本规范化只去除首尾和内部空白，用于计算不同值数量；不做业务词识别。固定单位如每行均为“万元”时只有一个不同值，不能替代边缘变化条件，因此仍保持现有合法合并行为。

## 数据流与约束

调用位置保持不变：

```text
native spans
  -> 视觉行聚类
  -> 现有 _can_join()
  -> 扩展后的 alignment corridor veto
  -> 独立 atoms
  -> 列带、物理 Cell、逻辑 Cell
```

实现只消费 `build_text_runs()` 已持有的 native span、visual row、bbox、字体和 flow 信息。不得调用 `page.get_text("words")`，不得在进入 atom、列带或 Cell 阶段后重新读取表格文字。

## 测试设计

先添加最小失败用例并确认 RED，再做最小实现：

1. Page 979 形态正例：至少 3 行不同宽度金额右对齐，右侧为多个不同但等宽的双字 CJK 值，存在稳定共同走廊；断言每行金额与地点保留为两个独立 atom。
2. 固定单位反例：多行数字右对齐，右侧固定为同一“万元”，其他几何条件相同；断言不因新条件否决合法合并。
3. 内容多样但见证不足反例：只有 1 至 2 行时保持现有行为。
4. 内容多样但走廊不稳定反例：共同空白交集不足时保持现有行为。
5. 既有对齐走廊、span 合并、输出顺序和无线结构测试必须继续通过。

页面级验收使用模型对 `fix/zh_all_table_pages.pdf` 页索引 `979` 重跑到新的独立输出目录。最终应得到 1 张 `wireless_span_recovery` 表，视觉叶子列为 8 列，“注册资本”和“主要经营地”分立；检查表格 bbox、行列数、表头 `rowspan/colspan`、空槽位物化、逻辑槽位唯一占用、组内/组间线框及最终 PNG，不得吸收页眉、标题或页脚。
