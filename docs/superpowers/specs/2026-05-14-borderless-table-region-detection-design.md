# 无线表格区域发现重构设计

日期：2026-05-14

## 目标

本次重构只解决“无线表格区域发现”，不直接解决列恢复、单元格切分、文本回填。

目标是从页面文本中稳定找到候选无线表格区域，并尽量减少正文误检。后续表格结构恢复单独处理，并回到原始 `word` 级文本。

## 范围

本阶段只覆盖三层中间表示：

1. `words -> fragments`
2. `fragments -> rows`
3. `rows -> candidate regions`

本阶段输出：

- 每页的候选区域 bbox
- 候选区域包含的 rows
- 用于调试的可视化和中间 JSON

本阶段不输出：

- 表格列边界
- 单元格
- 最终 `Table`
- Markdown / JSON 正式结果

## 核心约束

### 1. 预处理服务于“找区域”，不服务于“建结构”

`fragment` 和 `row` 的职责是降低 PDF 文本碎片噪声，让表格区域模式更明显。

它们可以容忍一定的文本合并失真，但不能作为最终表格结构恢复的输入。

### 2. 结构恢复必须回到原始 `word`

后续如果要做列检测、cell 归属、文本回填，必须重新使用原始 `page.get_text("words")` 结果，必要时结合候选区域 bbox 做局部分析。

### 3. 不依赖 PDF block

区域发现不以 `block` 为基本单位。`block` 仅保留作参考调试信息，不参与候选区域建模。

## 数据模型

建议新增或演进以下中间对象：

### `TextWord`

- `text`
- `bbox`

来源于 `page.get_text("words")`。

### `TextFragment`

表示经过保守归一化后的行内片段。

- `text`
- `bbox`

职责是把过碎 token 适度收拢成更稳定的原子文本单元，用于区域发现。

### `VisualRow`

表示页面上的一条视觉文本带。

- `fragments`
- `bbox`

职责是承载“这一行是否像表格行”的特征。

### `CandidateRegion`

表示候选无线表格区域。

- `rows`
- `bbox`
- `features`
- `score`

## 算法分层

### 第一层：`words -> fragments`

目标：减少 PDF 文本切分噪声。

策略：

- 仅做保守的行内近邻归一化
- 不尝试推列
- 不要求文本无损
- 不要求 fragment 可直接复用于 cell 恢复

这一层允许一定程度的过合并，只要有助于稳定发现表格区域。

### 第二层：`fragments -> rows`

目标：从碎片中构建稳定视觉行。

策略：

- 基于垂直重叠、中心线接近、行高相近，把 fragments 组成 `VisualRow`
- `row` 是区域发现的基本单位
- `row` 可以横向包含多个字段

### 第三层：`rows -> candidate regions`

目标：从连续 rows 中识别无线表格候选区域。

候选区域主要依赖以下信号：

- 行重复性：相邻多行是否反复出现类似的横向结构
- 列状对齐：若干 x 位置是否在多行中稳定重复
- 数值列特征：右侧是否存在持续出现的金额、比例、日期等列
- 行高和行距稳定性：表格区域通常比正文更整齐
- 行内稀疏性：正文更像连续文本流，表格更像离散字段组合
- 区域连续性：候选区应由连续多行构成，而不是单行命中

## 成功标准

当前阶段的成功标准定义为：

1. 普通段落页不应被大面积误判成表格候选区
2. 无线表格页的表格主体应能被圈成连续区域
3. 区域发现阶段允许文本合并失真
4. 但后续结构恢复必须能够回到原始 `word`

## Demo 计划

下一步先做独立原型，不接主流程：

1. 基于 `words -> fragments -> rows`
2. 为每页计算 `candidate regions`
3. 在样例 PDF 指定页上输出 overlay PNG
4. 叠加显示 `row bbox` 与 `candidate region bbox`
5. 导出中间 JSON 用于人工检查

目标是先回答一个问题：是否能稳定找对无线表格区域。

## 与现有代码的关系

当前 `table_extractor.py` 中的 `_extract_via_text_alignment()` 同时承担：

- 文本行聚合
- 候选区判断
- 列 guide 推断
- 表格结构恢复

这些职责耦合过重。

重构方向是先把“候选区域发现”独立出来，作为前置阶段。结构恢复后移，并改为单独消费原始 `word` 和候选区域。

## 风险

### 1. fragment 过度合并

如果 fragment 合并过强，可能弱化列边界。当前阶段可接受，但后续结构恢复不能依赖 fragment。

### 2. 正文中的对齐假象

中文财报正文中存在大量“看起来像列”的内容，必须依靠多行重复性和区域连续性抑制误检。

### 3. 横页与竖页混排

样例 PDF 同时存在横页和竖页，候选区域特征不能依赖固定页面方向。
