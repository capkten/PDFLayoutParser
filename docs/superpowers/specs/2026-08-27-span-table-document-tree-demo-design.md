# Span 表格文档树结构恢复 Demo 设计

## 目标

在模型已经提供准确 `table_bbox` 的前提下，只针对表格区域内部验证基于原始 PDF span 输出顺序的文档树/表格树恢复逻辑。Demo 不重新检测页面表格区域，不修改现有生产提取路径。

验证样例为 `fix/zh_all_table_pages.pdf` 第 184 页的账龄分析表，目标是识别两级表头和逻辑叶列：

```text
项目
年末数: 账面余额 / 比例 / 坏账准备
年初数: 账面余额 / 比例 / 坏账准备
```

## 设计

### 输入与原始信息

- 输入 PDF、0-based page index 和已知表格 bbox。
- 复用 `collect_native_spans()` 获取区域内 `NativeSpan`。
- 保留 `NativeSpan.order` 作为内容流顺序；视觉坐标只用于 bbox 关系和可视化校验。
- 保留字符级 bbox，为宽 span 内部拆分 phrase 提供依据。

### 树结构

Demo 内部建立以下节点：

- `table`：输入 bbox 对应的根节点。
- `header_group`：如“年末数”“年初数”。
- `leaf_column`：如“账面余额”“比例”“坏账准备”。
- `row`：数据行或表头行。
- `cell`：最终逻辑单元格，保存 `rowspan`/`colspan`。
- `text`：来自 span 或字符拆分的原子文本块。

表头采用父子关系表达跨列表头；父节点覆盖连续的叶列。数据为空不删除已由表头确认的叶列。

### 内容流与合并单元格

建立原始 `order` 序列，不用 `center_y/x0` 重排结构输入。

- 同一左侧列的多个文本块连续输出，随后才出现右侧数据块：作为纵向合并单元格候选。
- 左右文本按行交替输出：作为普通独立数据行候选。
- 原始顺序必须同时满足同列区间、垂直连续性和无交错右侧内容等几何约束；单独的输出顺序不能决定 rowspan。

### 宽 span 原子化

宽 span 先依据字符 bbox、长空白和明显横向间隔拆为 phrase，同时继承原始 span 顺序。该步骤只服务于 Demo，不改变现有 `_split_raw_field_strip()` 行为。

### 输出

- 树结构 JSON：保留节点类型、父子关系、原始顺序、bbox、rowspan/colspan。
- PNG 可视化：红色为输入 bbox，紫色为树节点范围，蓝色为叶列/逻辑 cell，橙色为原子文本块，并显示原始 order。
- 不输出 HTML，不修改生产 `TableExtractor`。

## 验收标准

对第 184 页账龄分析区域：

1. 表格根节点等于传入 bbox，不发生区域重新检测。
2. 能够得到 `项目` 加两组各三个叶列的表头树。
3. `比例` 作为叶列保留，即使部分 body 行为空。
4. 左侧连续三段文本可以形成 rowspan 候选；逐行交替内容不会被误合并。
5. 输出 PNG 能直观看到原始 span 顺序与树节点关系。
6. Demo 失败时保留中间节点和顺序证据，便于判断是 span 原子化失败还是树关系推断失败。

## 非目标

- 不重新识别页面或表格区域。
- 不过滤分割线文本。
- 不替换现有无线表格生产逻辑。
- 不在 Demo 阶段追求覆盖所有 PDF 生成器的内容流顺序。
