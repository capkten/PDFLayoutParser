# 二叶子列表头合并设计

## 背景

`fix/zh_all_table_pages.pdf` 的第 192 页已经恢复出三张无线表格，其中中表为 `5x9`，下表为 `5x5`。两张表的叶子列数量和正文归属正确，但多级表头仍有两类结构问题：

1. 居中的短一级标题没有覆盖其下方两个叶子列；
2. 左侧行标题位于中间表头层，上下被物化为空单元格，没有纵向覆盖完整表头高度。

中表的目标结构是：

- `年初数 -> C2:C3 -> 金额 / 比例`
- `本年增加 -> C4:C5 -> 金额 / 比例`
- `本年减少 -> C6:C7 -> 金额 / 比例`
- `年末数 -> C8:C9 -> 金额 / 比例`
- `企业名称 -> C1`，纵向覆盖全部表头层

下表当前页面顺序的目标结构是：

- `年末数 -> C2:C3 -> 金额 / 坏账准备`
- `年初数 -> C4:C5 -> 金额 / 坏账准备`
- `项目 -> C1`，纵向覆盖全部表头层

规则不能依赖“年初数”“金额”“坏账准备”等具体文本，也不能回读 page words。

## 根因

### 二列表头没有进入居中父跨度推断

`annotate_columns()` 已能根据文字 bbox 的实质覆盖设置 colspan，也有 `_infer_centered_parent_span()` 处理文字框较窄但视觉居中的父表头。然而该推断只枚举至少三个连续叶子列，因此二叶子列候选永远不会被考虑。

中表的“本年减少”因文字框恰好直接覆盖 C6、C7，当前已经得到 `colspan=2`；其他短标题只实质覆盖一个 band，因而保持 `colspan=1`。下表两个期间标题同样只覆盖一个 band。

### 首列表头所在物理行形成空槽

PDF 将一级组标题、首列标题和末级叶子标题排在三个不同 y 层。`build_grid()` 因此建立三个物理表头行，`materialize_empty_cells()` 再为首列标题上下和组标题下方补出空槽。

真实表头 rowspan 不能在 `build_logical_grid()` 之前设置。该函数会把任何被纵向单元格覆盖的物理行压缩到同一逻辑行；若提前让首列表头覆盖三行，父标题和叶子标题也会被映射到同一逻辑行并发生 occupancy conflict。

## 方案比较

### 方案一：按表头关键字合并

看到“年初数/年末数”就向右合并两列。实现简单，但无法覆盖其他中文财务表头，且容易在叶子列数量不同的表格上误合并，不采用。

### 方案二：最终 Cell 阶段看到右侧空格再合并

在空单元格物化后，将标题右侧的空格并入标题。该方法丢失了上下表头层的父子证据，无法区分“真实空列”和“父标题覆盖列”，不采用。

### 方案三：表头拓扑推断，逻辑网格后补 rowspan

横向合并复用已有居中父表头推断，将连续二叶子列纳入候选；纵向合并在逻辑网格生成后、空槽物化前，根据已经确认的父子表头层扩展 rowspan。该方案不依赖文本语义，且每个修改都位于拥有完整证据的数据层，采用此方案。

## 横向 colspan 设计

对位于叶子标题层上方的父标题，允许枚举两个或以上连续叶子列。二列候选必须同时满足：

1. 两个叶子列连续，且在同一个紧邻下层表头层都有真实标题 atom；
2. 候选包含父标题当前归属的列；
3. 父标题中心与两个叶子 band 外边界组成的物理区间中心对齐，误差不超过 `max(4pt, group_width * 0.08)`；
4. 父标题位于叶子层上方，而不是叶子标题自身；
5. 同一父标题层的候选按 x 顺序单调且互不重叠；
6. 若文字 bbox 已经直接实质覆盖两个叶子列，继续保留现有直接跨度结果。

二叶子列的物理宽度可以远大于父标题文字宽度。例如下表“金额”和“坏账准备”列宽不等，二列总宽约为短期间标题的四倍。因此二列候选不使用固定的最大“组宽/文字宽”比例作为硬条件；连续叶子、上下层关系、中心对齐和同层不重叠共同提供证据。

确认候选后，在 atom 上设置 `column_start`、`column_end` 和 `colspan`。`build_grid()` 随后直接生成横向合并单元格，被覆盖的同层槽位不再物化为空格。

## 纵向 rowspan 设计

在 `build_logical_grid()` 之后、`materialize_empty_cells()` 之前增加表头跨度整理。只有已经存在“父标题 + 下层叶子标题”的多级表头结构时才执行：

1. 确认父标题逻辑行、末级叶子标题逻辑行和二者之间的中间表头行；
2. 对 `colspan >= 2` 的父标题，若其覆盖列在父标题之后、叶子标题之前没有其他非空单元格，将其 `row_end` 扩展到叶子标题上一行；
3. 在父标题覆盖范围之外查找首列单标题；若该列在全部表头行只有这一个非空标题，将其 `row_start` 移到首个表头行，并将 `row_end` 扩展到末级叶子标题行；
4. 更新 `rowspan`，随后执行 occupancy conflict 校验；
5. 空单元格物化只补仍未被 rowspan/colspan 覆盖的槽位。

该规则不会合并正文空单元格，也不会跨越存在其他非空表头内容的槽位。最终保留当前三个物理表头层，但用 rowspan 表达正确结构：父组标题覆盖前两层，末级叶子标题位于第三层，首列表头覆盖全部三层。

## 数据流

修复后的数据流为：

`NativeSpan -> atom -> 叶子列带 -> 父标题 colspan 注解 -> 物理网格 -> 逻辑网格 -> 表头 rowspan 整理 -> 冲突校验 -> 空槽物化`

整个流程只消费已有 NativeSpan/atom、列带和逻辑单元格，不读取 page words，不在最终 normalizer 中按文本重建表格。

## 测试与验证

自动化测试覆盖：

1. 居中的父标题可覆盖两个连续、同层有真实标题的叶子列；
2. 多个同层父标题分别匹配相邻二列，候选互不重叠；
3. 宽度不等的两个叶子列仍能由短父标题覆盖；
4. 只有一个下层叶子标题或中心不对齐时不生成 colspan；
5. 父标题横向跨度不回归为三列以上错误扩张；
6. 中间行无其他内容时，父标题扩展到叶子层上一行；
7. 独立首列表头覆盖完整表头高度；
8. 中间存在其他非空表头时不进行纵向合并；
9. 合并后每个逻辑槽位恰好被占用一次，正文和空槽规则不变。

页面级验证重跑 page index 192，要求：

- 中表保持 `5x9`，四个期间标题均为 `colspan=2`；
- 下表保持 `5x5`，两个期间标题均为 `colspan=2`；
- `企业名称`和`项目`覆盖完整表头高度；
- 三张表均无 occupancy conflict；
- PNG 中组内一级表头竖线消失，组间边界保留，首列表头上下不再出现独立空格。

## 边界与风险

- 仅有标题居中但下层没有两个真实叶子标题时，不推断二列父级。
- 同一父层出现相互重叠的候选时，放弃有歧义的推断，不用最近距离强行选择。
- rowspan 整理位于逻辑网格之后，不能反向改变物理行聚类；它只表达已确认表头结构。
- 本次不压缩三个表头层为两个逻辑行，以免改变正文行号和现有物理轨迹；通过明确 rowspan 消除空槽即可得到等价的表头结构。
