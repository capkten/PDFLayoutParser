# Span 到 atom 字段边界修复设计

## 背景

`fix/zh_all_table_pages.pdf` 的第 192 页实际包含三张表，但旧结果只保留了最下方一张表，而且该表只有 4 列。检测模型并未漏检：页面上的真实表格区域均已形成高置信度候选。上方两张表是在中文/混合语言的 native-span 结构恢复阶段，因为多个文本 atom 被分配到同一网格位置并产生 occupancy conflict，最终被整表拒绝。

本修复只处理 `NativeSpan -> atom` 的字段边界，不改变检测模型、候选框筛选、行列恢复和冲突处理策略。

## Span 与 atom

- `NativeSpan` 是 PDF 原生文本层提供的样式片段，包含文本、bbox、字体、源位置和字符级 `char_boxes`。
- atom 是无线表格恢复使用的最小文本归属单位。atom 可以直接对应一个 Span，也可以是一个 Span 按明确字符间距拆出的字段片段；只有可以确认属于同一单元格的相邻 Span 才能合成一个 atom。
- Span 处理完成后，表格恢复不得重新读取 page words。后续行列推断、单元格归属和冲突判断只能消费已规范化的 Span/atom。

## 根因

### 独立 Span 被跨字段合并

page 192 的公司名称与相邻金额原本是两个独立 `NativeSpan`，但二者位于同一个 PDF 原生文本行且水平间距较小，`build_text_runs()` 将它们合成了一个宽 atom。该 atom 横跨项目列和金额列，导致列带不足或与其他 atom 竞争同一单元格。

需要阻止的模式是：前一个独立 Span 含中文，后一个独立 Span 是完整的数值字段或短占位符。它们即使位于同一原生行，也不能仅因几何接近而自动合并。

仍需保留的模式包括同一单元格内被 PDF 样式切开的文本，例如数字前缀与中文标签组成的“1年以内”，以及正文与上标脚注。规则不能简单禁止所有中文和数字相邻 Span 的连接。

### 单个 Span 打包多个字段

中间表存在 `5,100,000.00  51%` 和 `---  5,100,000.00  51%` 这类单个原生 Span。现有拆分器只接受不含百分号的纯数字字符集合，并且只拆第一个显著间距，因此金额、比例和占位符仍被保留为一个宽 atom。

字符级 `char_boxes` 在这些字段之间存在显著水平间距。应以字符位置为依据收集所有显著空白边界，将一个 Span 拆成两个或多个字段片段，并为每个片段重建 bbox、字符盒、来源片段编号和 `span_ref`。

### 邻列标题擦边形成伪列

完成文本边界修复后，中间表可以恢复，但一度得到 10 列而不是 9 列。列带诊断显示，“金额”所在 band 的右边缘与相邻“比例”标题仅重叠约 1.3pt；最低层表头细化使用“任意相交”收集子标题，将这个擦边标题误当成第二个子标题，于是额外拆出一个没有正文锚点的伪列。

项目已有 `_meaningful_header_band_overlap()` 用来区分有效覆盖和字形边缘擦碰。最低层子标题识别应复用该判定，只有对当前 band 形成实质覆盖的标题才能证明子列。

## 设计

### 1. 独立 Span 的连接保护

在 `text_runs._can_join()` 中增加窄规则：当两个项目是相邻的原生 Span，左侧文本包含中文，右侧文本整体是数值字段或短横线占位符时，不允许普通同原生行连接。数值字段允许千分位、小数、括号、正负号和百分号。

该规则不处理一个 Span 内部的字符，也不禁止“数字 Span + 中文 Span”，因此“1”与“年以内”仍可合并；已有上标逻辑继续优先服务脚注场景。

### 2. 打包字段的多段拆分

在 `span_chain` 中扩展现有 packed-field 识别：

- 仅处理由数字、金额标点、括号、正负号、百分号和横线占位符组成的 Span；
- 遍历字符盒，收集所有达到 `max(3.0pt, font_size * 0.45)` 的空白分隔边界；
- 忽略前导、尾随和连续空白，不产生空片段；
- 每个非空片段独立生成 bbox、`char_boxes`、`source_fragment_index/count` 和稳定的 `source_position`；
- 没有可靠字符盒或没有显著间距时原样返回，避免按文本猜测拆分。

### 3. 最低层表头的有效重叠

`_split_by_lowest_header_children()` 收集同一最低表头行的候选子标题时，使用已有的有效重叠判定，不再接受任意正面积相交。这样不会为邻列标题的轻微擦边新建列带，同时真实父表头下大面积覆盖当前 band 的多个子标题仍可完成叶子列拆分。

该修复作用于列带证据入口，不通过删除特定空列掩盖错误，也不改变最终空单元格物化规则。

### 4. 数据流约束

数据流保持为：

`NativeSpan -> region_spans() 字段拆分 -> build_text_runs() 谨慎连接 -> 行列推断 -> 单元格归属`

不增加 words 回读，不引入公司名、表头名称或 page 192 专用关键字，也不在 occupancy conflict 层吞掉冲突。

## 验证

自动化回归测试覆盖：

1. 独立中文标签 Span 与后续金额 Span 不合并；
2. “1”与“年以内”等合理的同单元格文本仍合并；
3. `金额 + 比例` 可拆成两个 atom；
4. `占位符 + 金额 + 比例` 可拆成三个 atom；
5. 普通中文数字混合 Span 和无显著字符间距的字段不误拆。
6. 邻列标题只擦碰 band 边缘时不产生额外叶子列，实质覆盖的多子标题仍可拆列。

页面级成功标准：对 `fix/zh_all_table_pages.pdf` 的 0-based page index 192 单页重跑，得到三张表；注册资本变化表为 5 个叶子列，关联方持股变化表为 9 个叶子列，关联方未结算项目表为 5 个叶子列；真实表格不再因 occupancy conflict 被拒绝。最终同时检查结构化输出和独立输出目录中的可视化 PNG。

## 风险与边界

- 某些 PDF 会将同一单元格的中文名称和数值确实拆成两个 Span。当前规则选择将“中文字段 + 完整数值字段”视为列边界，这是财务表结构恢复中更保守的默认值；跨列合并造成的结构损害大于保留两个 atom。
- packed-field 拆分依赖字符盒的真实间距。字符盒缺失或映射不完整时保持原 Span，不使用字符数均分 bbox。
- 表头细化仅收紧最低层子标题的重叠证据，不改变正文数值轨迹拆列和空单元格物化。若其他页面依赖不足 5.5pt 的标题重叠证明真实子列，应优先补充正文或兄弟标题证据，而不是恢复“任意擦边即拆列”。
