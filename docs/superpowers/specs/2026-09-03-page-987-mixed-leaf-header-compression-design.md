# Page 987 混合单行与折行叶表头压缩设计

## 背景与根因

`fix/zh_all_table_pages.pdf` 页索引 `987` 的中文无线表格应为 `6x7`：两行表头加四行正文。当前全量结果却为 `7x7`、45 个 Cell，表头被拆成三行，并物化出多余空槽位。

native-span 到 atom 阶段已经正确保留并组合“合营企业或联营\n企业名称”“主要\n经营地”等字段，七个列带也正确。“持股比例(%)”已恢复为覆盖第 5、6 列的 `colspan=2` 父表头。问题发生在后续物理行与逻辑行转换：收紧后的同列物理行判定将竖向排版的“间”“接”分到两个物理行，之后 `merge_multiline_cells()` 把它们合成跨行叶表头；同层的“直接”是单行叶表头。现有 `_wrapped_leaf_header_span()` 要求候选起始行上的所有非空 Cell 都是多行叶表头，因此因同一行还有前四个普通单行标题而拒绝压缩。最终“直接”和“间接”不在同一逻辑行，父表头无法完成完整的 `1:2` 子列证明，前四列与最后一列的 `rowspan` 也随之恢复失败。

使用相同 native span、atom 和列带，仅在内存中切回收紧前的物理行聚类行为，本页恢复为 `6x7`、36 个 Cell，occupancy conflict 为 0。这证明需要补充的是逻辑行压缩对“父表头下混合单行/折行叶标题”的支持，而不是改动文字组合、列带或空槽物化。

## 目标

- 在不放宽通用物理行聚类阈值的前提下，将同一二叶子父表头下的单行与折行叶标题压缩到同一逻辑表头行。
- 只接受完整、连续、无重叠的 `1:2` 父子拓扑证明。
- 保留真实多级表头、普通单行表头和不完整父子关系的现有行为。
- 压缩后继续执行 occupancy conflict 检查；任何冲突都不得进入最终表格。
- 全程只消费 native span、atom、列带、物理 Cell 和逻辑 Cell，不调用 `page.get_text("words")`，不进入 zebra 或 legacy 重建。

## 非目标

- 不回退或放宽 `grid.py` 的同列纵向重叠规则。
- 不根据“持股比例”“直接”“间接”等业务文字判断结构。
- 不在空单元格物化后删除行或重排 Cell。
- 不支持缺少父表头证明的任意单行/折行标题压缩。
- 不改变 `merge_multiline_cells()` 的文本组合条件。

## 方案比较

### 方案 A：放宽物理行聚类

恢复旧的同行聚类可让 Page 987 重新得到正确结果，但会破坏 `c68079e` 为 Page 1014、435 等页面加入的同列互斥保护，使真实上下层标题重新被吸附到同一物理行。该方案影响范围过大，不采用。

### 方案 B：空槽物化后修剪多余行

根据空槽位比例删除表头行只能处理最终症状。此时父子层级已经丢失，无法可靠区分真实空表头、纵向合并和错误拆行。该方案不满足拓扑恢复约束，不采用。

### 方案 C：父表头证明下的逻辑行压缩

在 `logical_grid.py` 中新增受限分支：只有折行叶标题位于一个已确认的二叶子父表头之下，且父表头的两个连续子列均具有唯一叶标题时，才允许折行叶标题与同层单行叶标题共享的物理行区间压缩。该方案不改变上游召回和物理行保护，影响最小，采用此方案。

## 核心判定

新增一个私有纯函数，用于识别“父表头证明下的混合叶表头区间”。候选必须同时满足：

1. 候选 Cell 位于 `header_cutoff` 之上，是单列 `multiline_cell`，包含换行，且 `row_end > row_start`。
2. 候选上方存在唯一父 Cell；父 Cell 恰好覆盖两个连续列，且候选列属于其覆盖范围。
3. 父 Cell 的两个子列在候选物理行区间内各有且仅有一个非空、单列叶标题。
4. 一个子标题可以跨多个物理行，另一个可以是单行，但二者的行范围都必须完全落在候选区间内，且两个子标题的列集合恰好等于父 Cell 覆盖列集合。
5. 两个子列内不存在额外标题、重复起点或占位重叠。
6. 候选区间内不得启动任何 `colspan > 1` 的 Cell，避免折叠真实的下一层父表头。
7. 父表头覆盖范围之外的标题列，在候选区间内每列至多存在一个非空单列 Cell；这些 Cell 作为可能的纵跨 stub 保留，不参与父子证明，也不能形成竞争占位。
8. 任一条件不成立时返回 `None`，保持现有逻辑行分组。

判定只输出待压缩的物理行区间，不直接修改 Cell 的 `rowspan/colspan`。`_row_components()` 合并该区间后，继续由现有 `merge_header_spans()` 完成父表头、叶表头和 stub 的跨度恢复。

## 数据流与调用位置

调用位置保持在 `src/hexai_pdf_parser/tables/wireless_structure/logical_grid.py`：

```text
物理 Cell
  -> 现有 continuation-only 行压缩
  -> 现有纯折行叶表头区间识别
  -> 新增二叶子父表头证明下的混合叶表头区间识别
  -> build_logical_grid()
  -> merge_header_spans()
  -> occupancy conflict 检查
  -> materialize_empty_cells()
```

新分支不能访问页面对象，也不能重新读取文字。物理行仍由 `grid.py` 的严格同行规则产生，避免恢复此前已经修复的父子标题同槽位冲突。

## 测试设计

### 目标正例

- 构造 Page 987 形态：第 5、6 列上方有 `colspan=2` 父表头；第 5 列为单行叶标题，第 6 列为跨两个物理行的折行叶标题；前四列存在同区间单行 stub；第 7 列为跨完整表头的 Cell。
- 验证物理表头压缩为两个逻辑行，父表头保持 `colspan=2`，两个叶标题位于同一逻辑行，前四列和第 7 列恢复 `rowspan=2`。
- 空槽物化后不得产生空表头 Cell，所有逻辑槽位唯一占用。

### 拒绝反例

- 没有父表头时，即使存在单行与折行标题，也拒绝压缩。
- 父表头只找到一个子标题，拒绝压缩。
- 任一子列存在重复或竞争标题，拒绝压缩。
- 候选区间内存在另一个跨列父表头，拒绝压缩。
- 父表头覆盖三列或子列不连续，拒绝压缩。
- 父表头覆盖范围之外的同一列存在两个独立标题，拒绝压缩。
