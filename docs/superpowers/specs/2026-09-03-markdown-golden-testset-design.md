# Markdown 黄金测试集设计

## 1. 背景与目标

`fix/zh_all_table_pages.pdf` 已完成一轮大规模页面解析和可视化验证。当前结果保存在：

```text
output/fix_zh_all_table_pages_rerun_20260903/
```

逐张查看全部页面成本较高。本方案建立一份仅供本地使用的黄金测试集，后续通过一次自动比较即可发现解析结果中的结构或文本变化。

目标是验证 PDF 提取结果是否满足以下条件：

- 正文文本正确；
- 表格数量和表格出现顺序正确；
- 表格行列结构正确；
- 单元格位置、空槽位和 `rowspan`/`colspan` 正确；
- 单元格文本正确。

不把 bbox、置信度、渲染路径和图片像素作为自动测试的通过条件。PDF 解析中的坐标细微变化不应导致测试误报。

## 2. 范围与输入

### 2.1 输入 PDF

```text
fix/zh_all_table_pages.pdf
```

原 PDF 共 1023 页。当前已成功生成结果的页面作为候选标签来源。

### 2.2 页面范围

- 纳入所有成功生成可视化结果的页面；
- 纳入已确认正确的可视化图片 `...part_003_pages_0513_0683...page_076.png`；
- 排除已确认错误的可视化图片 `...part_004_pages_0458_0486...page_024.png`；
- 两个解析报错页因没有有效结构化结果，不生成黄金标签。

标签生成过程必须根据输出目录中的页面范围和页码信息恢复原 PDF 页索引，不能仅使用分片 PDF 内部的局部页码。发现页码映射不唯一或无法验证时，应报告冲突并停止生成该页标签，不能静默覆盖。

## 3. 方案对比

### 3.1 完整 JSON 逐字比较

优点是信息完整，可以直接获得所有模型字段。

缺点是 JSON 同时包含 bbox、置信度、渲染路径、图片路径等不稳定字段。解析逻辑只发生坐标微调时，也可能产生大量无意义差异。因此不作为主方案。

### 3.2 原始 Markdown 逐字比较

优点是复用现有 `MarkdownWriter`，实现和人工检查都很快。

缺点是页面中的图片路径可能随输出目录变化，换行和空白格式也可能产生无意义差异。直接比较整个文件不够稳定。

### 3.3 规范化 Markdown 比较（采用）

Markdown 已经包含正文文本和 HTML 表格，表格中保留了单元格文本、空单元格、`rowspan` 与 `colspan`。在比较前做确定性的规范化：

- 删除图片引用及其路径；
- 统一换行符；
- 统一文件末尾空白和无意义空行；
- 保留正文实际文本；
- 保留 `<table>`、`<tr>`、`<td>` 的顺序和结构；
- 保留 `rowspan`、`colspan` 属性；
- 保留空 `<td></td>`；
- 不比较 bbox、置信度、图片路径和输出路径。

比较器以规范化后的 Markdown 为主，失败时额外输出人类可读的 Markdown 差异报告。这样既复用现有输出，又能避免路径和渲染元数据导致误报。

## 4. 本地目录结构

测试集保存在：

```text
output/fix_zh_all_table_pages_rerun_20260903/testset_markdown/
```

目录结构：

```text
testset_markdown/
├── labels/
│   ├── page-000.md
│   ├── page-001.md
│   └── ...
├── manifest.json
└── README.md
```

### 4.1 `labels/`

每个标签文件以原 PDF 的 0-based 页索引命名，而不是以分片 PDF 的局部页索引命名。标签内容来自当前已验证的页面 Markdown 输出。

标签文件只作为本地黄金基线，不提交到 Git，不上传到仓库。

### 4.2 `manifest.json`

Manifest 用于保证标签来源可追溯，包含：

- 输入 PDF 的绝对路径和规范化路径；
- 输入 PDF 页数；
- 标签生成时间和生成工具版本信息；
- 原 PDF 页索引；
- 标签文件路径；
- 当前结果来源的页面 JSON 和可视化图片路径；
- 是否存在 Markdown；
- 无 Markdown 的扫描页记录；
- 排除的错误图片及排除原因；
- 解析报错页及错误信息；
- 页码映射校验结果。

Manifest 中的路径用于追溯，不参与结构和文本比较。

### 4.3 `README.md`

说明本地测试集的生成时间、输入文件、排除项、运行方式、比较规则和已知限制，避免后续误把黄金标签当成最新实际结果。

## 5. Markdown 规范化与比较规则

### 5.1 文本规则

- 保留正文和单元格文本的实际字符内容；
- 将 `CRLF` 和 `CR` 统一为 `LF`；
- 去除行尾空白；
- 保留有意义的单词间空格；
- 不使用模糊相似度，不忽略字符增删；
- MarkdownWriter 已有的换行转空格、数字空格清理规则视为标签生成规则的一部分，实际结果必须使用同一 Writer。

### 5.2 表格结构规则

按 HTML 表格节点顺序比较：

- `<table>` 数量和顺序；
- 每个 `<tr>` 的数量和顺序；
- 每行 `<td>` 的数量和顺序；
- 每个 `<td>` 的 `rowspan` 与 `colspan`；
- 空单元格是否存在；
- 单元格文本。

不通过只要发生以下任一变化：

- 表格被漏检或多检；
- 行列结构变化；
- 空槽位被吞掉或新增；
- 跨行/跨列关系变化；
- 单元格文本发生变化。

### 5.3 无 Markdown 页面

当前 `MarkdownWriter` 对扫描页不生成 Markdown。Manifest 对这些页面记录 `markdown_status=absent_expected`，比较器将其解释为“该页期望没有可比较 Markdown 内容”，而不是把它当作标签缺失。

如果新运行中扫描页突然产生 Markdown，比较器应报告状态变化，供人工确认。

### 5.4 图片引用

Markdown 中的图片引用不参与比较。图片仍由现有 `visualized_images` 目录保留，用于人工复核失败页面。

## 6. 数据流

```text
当前解析输出
  ├─ pages/*.md       → 读取正文和表格
  ├─ pages/*.json     → 校验页面/分片映射
  └─ tables/*.png     → 记录可视化来源
          ↓
    生成 manifest
          ↓
    复制有效 Markdown 到 labels/
          ↓
重新解析输入 PDF
          ↓
    生成实际 Markdown
          ↓
    规范化 expected / actual
          ↓
    比较文本和表格结构
          ↓
通过，或输出 Markdown 差异报告
```

## 7. 错误处理

- 标签来源文件不存在：立即报告并停止生成，不创建不完整测试集；
- 页码映射冲突：报告所有候选路径，不自动选择；
- 排除图片不存在：报告警告，并要求确认是否继续；
- 新结果缺少 expected 标签：测试失败；
- 新结果出现 expected 未记录的页面：测试失败；
- Markdown 内容差异：保留实际 Markdown，并输出差异文件；
- JSON 只用于映射校验和失败定位，不改变 Markdown 主比较规则。

## 8. 验收标准

方案实现后应满足：

1. 本地 `testset_markdown/labels/` 能覆盖所有纳入页面；
2. `page_024.png` 不出现在纳入清单中；
3. `page_076.png` 出现在纳入清单中；
4. 标签与原 PDF 页索引映射可由 Manifest 复核；
5. 对当前同一批结果运行比较器，结果为通过；
6. 人为修改一个单元格文本、`rowspan` 或空槽位后，比较器能失败并指出页面；
7. bbox 或输出路径变化不会导致比较器失败；
8. 测试集和中间临时文件均不进入 Git；
9. 现有 `fix/` 输入目录和用户已有工作区改动保持不变。

## 9. 取舍结论

采用“规范化 Markdown 作为黄金标签，Manifest 负责来源和异常页管理，JSON 只作辅助诊断”的组合。它满足当前只关心结构和文本的要求，复用现有输出，生成和后续比较都较快，同时保留了失败后的人工定位能力。
