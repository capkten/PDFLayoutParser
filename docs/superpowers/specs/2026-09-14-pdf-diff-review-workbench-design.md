# PDF 差异分类与审阅工作台设计

## 目标

针对 `fix/zh_all_table_pages.pdf` 的全量端到端输出，逐页对比标签 Markdown，识别当前结果与标签之间的差异类型，并生成可供人工判断的静态审阅工作台。当前审阅基线使用 2026-09-14 新鲜重跑结果；旧缓存显示的 146 页差异只作为历史参考，不作为本次分类依据。

## 已确认基线

- 输入 PDF：`fix/zh_all_table_pages.pdf`，1023 页。
- 标签 manifest：`output/fix_zh_all_table_pages_rerun_20260903/testset_markdown/manifest.json`。
- 标签覆盖：943 个 Markdown 页面、79 个预期无 Markdown 的扫描页、1 个排除页。
- 新鲜 E2E：`901 passed / 121 failed / 1 skipped`，缺失页和额外页均为 0。
- 新鲜输出：`output/fix_zh_all_table_pages_review_20260914/`。

## 分类规则

分类器先对标准化 Markdown 解析为正文片段和 HTML 表格结构，再比较标签与当前结果：

1. `reading_order`（阅读顺序）：表格和正文的可见文本集合相同，但段落/单元格顺序不同；不把图片路径、空白差异当成错误。
2. `table_structure`（表格结构）：表格数量相同，单元格文本集合基本相同，但行列、`rowspan`、`colspan`、单元格边界或结构标签不同。
3. `table_text`（表格文本）：表格结构相同，表格单元格文本存在增删或替换。
4. `table_count`（表格数量）：表格数量不同，或表格被误并/误拆。
5. `body_text`（正文文本）：表格之外的正文文本存在增删或替换。
6. `mixed`（混合差异）：同时命中两个或更多上述主类，优先保留所有命中类型供审阅。
7. `formatting`（格式差异）：仅 HTML 属性顺序、空白、换行或 Markdown 形式变化，且可见语义不变。

分类结果必须携带判定证据：标签/当前字符数、表格数、行列/跨度摘要、正文是否变化、统一 diff 文本及分类置信说明。分类器不替人工判定“哪一个正确”。

## 输出与界面

所有产物写入新鲜输出目录下的 `review/`：

- `classification.json`：包含基线、统计、页面记录、相对资源路径和默认分类。
- `summary.json`：分类计数、E2E 状态、输入与标签路径。
- `images/page-XXX.png`：左侧标签基准表格图，右侧当前结果表格图；图片缺失时保留页面记录并显示原因。
- `index.html`：无后端、双击即可打开的中文审阅工作台。

页面布局为左侧页面列表、中间并排图、右侧 Markdown diff。左侧支持分类筛选和页码/文本搜索；中间支持原图放大；右侧显示增加/删除行。每页提供“保留当前”“保留标签”“待确认”三个互斥选择，默认“待确认”；选择写入浏览器 `localStorage`，并提供下载当前审阅决策 JSON 的按钮。

## 数据流与安全边界

生成器只读取输入 PDF 的已生成输出、标签 manifest/Markdown、当前输出 JSON/Markdown/表格 PNG 和 diff 文件，不修改原始 PDF、标签文件或 E2E 结果。HTML 只引用自身目录内的相对文件，不启动服务、不执行外部请求；Markdown 内容进入 HTML 前必须转义。生成器运行前检查页面索引覆盖、资源路径和 diff 页面一致性。

## 测试与验收

- 单元测试覆盖分类规则：仅阅读顺序、结构变化、表格文本变化、表格数量变化、正文变化、混合变化、纯格式变化，以及 HTML/Markdown 转义。
- 生成器测试使用临时目录验证 `classification.json`、图片复制/拼接、HTML 资源链接和无差异/缺资源页面。
- 在真实 1023 页输出上运行生成器，核对分类计数总和为 121，页面索引无重复、无缺失。
- 随机抽查代表页（包括 008、193、335、338、341、342）时同时查看 JSON、Markdown diff 和并排 PNG；视觉判断由独立图像审阅流程完成。
- 不自动修改标签，不自动选择“保留当前”或“保留标签”，不自动提交、推送或发布。
