# 叶子表头单次支持列恢复设计

## 目标

修复中文和混合页面中“表头存在、整列正文为空”的无线表格结构丢失问题。以 `fix/zh_all_table_pages.pdf` 页索引 `923` 为目标页，将“备注”恢复为最右侧独立叶子列，使该表从冲突的四列结构恢复为 `6x5` 完整逻辑网格。

本设计只放宽直接对应数据列的叶子表头，不降低普通 atom 形成稳定列带所需的跨行支持要求，也不把多级表头的父标题提升为独立叶子列。

## 根因

目标页识别为 `zh`，没有有线表格。ML 模型以 `0.9721` 置信度检测到 bbox `[83.5, 509.3, 505.5, 636.4]`，因此问题不在模型召回。

native-span 恢复在模型框中得到 25 个 atom。前四列均有表头和多行正文，在 x 方向形成四条重复轨迹；最右侧“备注”只有表头，正文五行均为空。`infer_column_bands()` 要求同一 x 组件至少包含两个 atom 且覆盖两个 y 层级，因此该 atom 不能形成稳定列带。

现有 `rescue_header_only_note_bands()` 只恢复第一条和第二条稳定列带之间的附注引用列，并要求文字符合 note-reference 形式。目标列位于所有稳定列带右侧，且“备注”不是附注编号引用，因此不会被恢复。后续最近列分配把“备注”和“摊销方法”同时放入第 4 列，产生 `R1C4` occupancy conflict；`recover_cells_from_region()` 按冲突约束返回空结构，最终整表不输出。

## 方案

### 1. 保持稳定列带门槛

`infer_column_bands()` 的普通列带仍要求跨行重复支持。不得把全局支持数从二降为一，避免正文标题、单位、说明文字和偶发孤立 atom 变成伪列。

### 2. 恢复叶子表头单次支持列

在稳定列带完成初始推断和裁剪之后、atom 列标注之前，增加通用的 header-only leaf 恢复步骤。候选必须同时满足：

- 位于已推断的表头范围内；
- 属于直接对应数据列的叶子表头层，而不是其上方父表头层；
- 与同层至少两条已确认叶子列共同组成横向表头行；
- 不与任何现有列带产生有效水平重叠；
- 与相邻叶子表头之间存在明确的列间距，不能只是同一字段被拆开的相邻 span；
- 位于可信表格 region 内；
- 插入后列序保持单调，且不会制造已有 occupancy 冲突。

候选可位于稳定列带之间，也可位于最左或最右端。判定只消费 native span、atom、表头层级、列带和 region 几何，不匹配“备注”“金额”“比例”等业务文字。

### 3. 叶子层判定

多级表头中只允许最接近正文、直接覆盖物理数据列的表头层提供单次支持列。父标题即使与现有列带不重叠，也不能形成新列。

叶子层证据由现有 header cutoff、同层 y 聚类以及该层对稳定列带的覆盖共同给出。若无法唯一确定叶子层，或同层候选可能是跨列父标题，则拒绝补列，保持当前稳定列带。

### 4. 后续网格职责不变

调用顺序为：

```text
native span
  -> atom/text run
  -> 稳定列带
  -> 叶子表头单次支持列恢复
  -> atom 列标注
  -> 物理 grid
  -> occupancy conflict 检查
  -> 逻辑 grid 与 rowspan/colspan 恢复
  -> 空槽逐格物化
```

补出的列带参与正常列边界推断。正文缺失槽位由现有 `materialize_empty_cells()` 分别生成 `text=""`、`1x1` Cell，不合并相邻空单元格。任何冲突结果仍不得进入最终表格。

## 测试设计

严格测试先行：

1. 增加 page 923 最小失败用例，确认最右侧仅表头列被恢复，结果为 `6x5`，第五列正文为空槽。
2. 增加几何单元正例，覆盖稳定列带之间和最右端的叶子表头单次支持列。
3. 增加反例：多级父表头、表头外孤立说明、与已有列带过近的同字段片段不得形成新列。
4. 运行既有 header topology、columns、recoverer 和相关 page 回归测试，确认附注窄列、父表头跨度与空槽物化行为不回归。

每个新增行为必须先观察到因当前实现缺失而失败，再做最小生产代码修改使其通过。

## 页面级验收

使用 `fix/zh_all_table_pages.pdf` 页索引 `923`，输出到新的独立目录：

```text
output/fix_page_923_header_only_leaf_20260902/
```

验收内容：

- 页面语言为 `zh`，表格 source 为 `wireless_span_recovery`；
- 目标表为 `6x5`，表头五列分别保留，最右列正文空槽逐格存在；
- 每个逻辑槽位恰好被一个 Cell 占用，无 occupancy conflict；
- bbox 不吸收上下正文，首个数据行的两行文字仍属于同一单元格；
- PNG 中表格边界、五列网格和上下三条横线对应合理；
- 聚焦测试、相关回归测试和 `git diff --check` 通过。

## 非目标

- 不降低所有列带的重复支持门槛；
- 不按“备注”等业务文字硬编码；
- 不恢复 `extract_zebra()` 或 legacy words 二次重建；
- atom 和网格阶段不调用 `page.get_text("words")`；
- 不修改英文、有线表格或无关页面行为；
- 不清理或回退工作区已有改动。
