# 中文财务表 native-span 冲突恢复设计

## 背景

`page-439` 上方三列表格和 `page-440` 长期股权投资宽表均已被当前 ONNX 模型检测。最终漏表发生在模型框内的中文 native-span 结构恢复阶段，而不是候选生成或模型检测阶段。

- `page-439` 在物理网格阶段产生槽位冲突。视觉上属于同一多行字段的 span 未在 atom 阶段完整组合，进入列带和 Cell 阶段后占用了相同槽位。
- `page-440` 的物理网格和初始逻辑网格无冲突；`merge_header_spans()` 调整多级表头跨度后产生 occupancy conflict，当前调用方因此丢弃整张表。

本设计只修复这两类根因，不放宽最终 occupancy conflict 不变量，不引入业务文字硬编码，也不回读 `page.get_text("words")`。

## 目标

1. 在 span 到 atom 阶段完成有证据的多行字段组合，使 `page-439` 在进入物理网格时不再产生槽位冲突。
2. 将多级表头跨度恢复改为整层事务式提交，使 `page-440` 在跨度推断冲突时保留无冲突的基础逻辑网格，而不是丢弃整张表。
3. 保持所有最终逻辑槽位恰好由一个 Cell 占用，空槽继续物化为独立 `1x1` 空 Cell。

## 非目标

- 不按“项目”“本期增减变动”等文字匹配表格类型或表头层级。
- 不在 atom、列带、物理 Cell 或逻辑 Cell 阶段读取 page words。
- 不通过忽略冲突、删除冲突 Cell 或保留重叠跨度来换取输出。
- 不回退到 `extract_zebra()`、legacy `_rebuild_text_aligned_table()` 或其他旧无线重建路径。

## 方案一：物理行带内的多行 atom 组合

### 输入证据

组合只消费模型区域内的 native span 及其既有来源信息。允许使用以下证据：

- span 的水平重叠或稳定列归属；
- 相邻视觉行的垂直距离；
- native flow 或 span 输出顺序的严格连续性；
- 连续输出的上下文本之后，存在位于右侧且覆盖联合行带的同记录字段，作为“先完整输出左侧单元格、再输出右侧单元格”的见证；
- 区域内水平分隔线形成的物理行带，保证组合不跨越表头、正文或汇总行边界；
- 同一候选字段内部不存在并列的独立叶子字段。

### 判定

两个或多个 span 只有同时满足以下条件才组合为一个 atom：

1. 后一段的 `flow_start` 恰好等于前一段的 `flow_end + 1`，在 PDF native 输出中严格连续；
2. 后一段位于前一段下方，x 区间明显重叠或左右锚点稳定；
3. 两段字体、粗体和文本类型兼容，y 间距不超过基于字体大小计算的正常换行限制；
4. 后续有限个输出项中存在右侧见证字段。见证字段的 x 起点明显位于待组合字段右侧，且其 y 范围与两段文本的联合行带相交；
5. 两段位于同一个水平分隔行带，组合不会跨越其他 atom，也不会吞并同一行带内的独立字段；
6. 保留可审计的 flow、span、block 和 line 来源信息。

右侧见证不要求与第二段文字处于同一基线。财务表中的右侧单元格可能在多行字段范围内垂直居中，因此使用其 bbox 与联合行带的相交关系判定。

以下任一情况成立时拒绝组合：

- 两段都是独立金额或占位符；
- 两段之间存在穿过候选列的水平分隔线；
- 右侧存在分别与上下两段对应的独立字段，表明它们属于两个物理行；
- 输出顺序不连续，或需要跳过其他字段才能形成组合；
- 只能依据“落入同一候选槽位”判断，缺少上述来源和拓扑证据。

组合结果以换行保留视觉行，合并 `span_refs`、`source_blocks` 和 `source_line_start/end`。完成 atom 构造后，后续阶段不得仅因两个对象落入同一槽位再次组合。

### `page-439` 预期

表头和正文各形成三个字段 atom：左列、中央多行说明列、右侧多行原因列。`build_grid()` 输入中不再存在同槽位的拆分字段，物理 occupancy 检查通过。

## 方案二：多级表头跨度的事务式提交

`merge_header_spans()` 不直接修改唯一的逻辑网格结果。调用流程调整为：

1. 保存无冲突的基础逻辑 Cell 集合；
2. 在完整副本上推断当前表头层的 `rowspan/colspan`；
3. 对整层结果重新执行 occupancy conflict 检查；
4. 无冲突时提交整层结果；
5. 任一跨度导致冲突时放弃整层推断，返回原始基础逻辑 Cell 集合；
6. 在最终选定的 Cell 集合上物化空槽。

事务回退不输出部分成功、部分失败的表头层，避免同一层出现不一致拓扑。回退后的基础网格必须继续通过 occupancy 检查，因此表格可以安全进入最终结果。

### `page-440` 预期

基础宽表列带、金额列和占位符均保留。若当前多级表头拓扑能够无冲突恢复，则提交跨度；否则先输出无跨度但无冲突的完整逻辑网格，不再返回空表。

## 数据流

```text
模型 bbox
  -> native spans
  -> 水平行带约束下的 text runs / atoms
  -> 列带
  -> 物理 Cell 与物理 occupancy 检查
  -> 多行 Cell 合并
  -> 基础逻辑网格与 occupancy 检查
  -> 表头跨度副本推断
       -> 无冲突：提交跨度网格
       -> 有冲突：回退基础逻辑网格
  -> 独立空 Cell 物化
  -> 最终表格
```

## 测试设计

测试先行，至少覆盖：

1. `page-439` 形态正例：同一字段的多行 native span 在 atom 阶段组合，物理网格无冲突，恢复 `2x3` 表格。
2. atom 反例：几何上落入同一候选槽位、但缺少 native 连续性或存在并列字段的 span 不得组合。
3. `page-440` 形态正例：基础逻辑网格无冲突；表头跨度推断冲突时回退基础网格，表格仍然输出。
4. 表头正例：完整、无重叠的父子拓扑仍可提交 `rowspan/colspan`。
5. 表头反例：同层任一组不成立时放弃整层推断，不保留部分跨度。
6. 既有 native-span、空槽物化、occupancy 和表头拓扑相关测试继续通过。

## 失败处理

- 物理 Cell 在 atom 修复后仍有 occupancy conflict：拒绝该结构结果，并在诊断中保留具体冲突槽位和来源 atom，不输出重叠表格。
- 表头跨度推断产生 occupancy conflict：只回退跨度层，保留已验证的基础逻辑网格。
- 任一最终结果存在 occupancy conflict：不得进入最终表格。
