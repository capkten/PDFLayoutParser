# 中文无线表格跨列可疑合并的对齐轨迹与空白走廊否决设计

## 背景与根因

`fix/zh_all_table_pages.pdf` 页索引 `960` 的上下两张中文无线三线表被模型正确检测，但 native-span 结构恢复返回空表。原因是金额字段和下一列文本字段在同一 native line 中连续，间距约 `3.232pt`，被现有 span 到 atom 的通用间距规则合成为一个 atom，例如 `1,734,597.85诉讼冻结`。列带因此从视觉上的 5 列退化为 4 列，后续网格出现同槽位冲突并拒绝整表。

仅调大或调小间距阈值无法稳定解决：阈值过大时独立列被合并，阈值过小时同一字段的编码/字体碎片无法组合。页面还提供了更强的几何证据：金额多行稳定右对齐，`诉讼冻结`、`借款抵押` 等文本多行稳定左对齐，两者之间存在重复的窄空白列缝。

## 目标

- 在 span 到 atom 的同视觉行组合阶段，增加保守的跨列合并否决条件。
- 只在“稳定成对对齐轨迹”与“重复空白分隔走廊”同时成立时拒绝当前合并。
- 保留现有顺序、来源连续性、字体和间距规则作为合并主判定；对齐关系只有 veto 权，没有主动合并权。
- 使用 native span 及其 bbox/来源元数据完成判断，不调用 `page.get_text("words")`。
- 让 Page 960 风格的金额列与文本列保持独立，同时不破坏真实的同字段碎片合并。

## 非目标

- 不通过全局收紧或放宽通用间距阈值解决该问题。
- 不让对齐关系主动合并原本因距离过大而未合并的片段。
- 不依赖“诉讼冻结”“借款抵押”等业务文字白名单。
- 不修改斑马纹、legacy 文本重建、列带之后的物理/逻辑网格职责。
- 不回读 page words，不把对齐判断下沉到结构恢复后再补救。

## 核心判定

对每个待合并的相邻 span/run，先执行现有 `_can_join()`。只有当 `_can_join()` 判定“可以合并”时，才执行新的对齐 veto：

```text
现有顺序/同行/来源/间距判定允许合并
        AND
稳定成对对齐轨迹
        AND
重复空白分隔走廊
        => veto，保留两个独立 run
```

任一几何证据不足，都保持现有合并结果。

### 稳定成对对齐轨迹

- 在当前 region 的未合并 native span 中按视觉 y 聚类行。
- 为每行的候选字段记录左边界 `x0`、右边界 `x1` 和中心点。
- 数字/金额字段优先使用右边界作为对齐锚点；普通文本字段优先使用左边界；居中只作为弱证据，不能单独触发 veto。
- 左右两组字段必须在至少 3 个不同视觉行中共同出现；这 3 行可以包含当前行，但必须至少有 2 个其他视觉行作为外部见证。
- bbox 抖动容差统一取 `max(1.0pt, min_font_size * 0.12)`。同一组锚点在支持行中的最大值与最小值之差不得超过该容差；两组轨迹顺序稳定，不交叉。
- 当前待合并的两个 span 必须分别落入这两组轨迹，其锚点到对应轨迹中位数的距离不得超过同一 bbox 抖动容差。
- 居中轨迹只有在另一侧存在稳定的左/右边界轨迹，且后述共同空白走廊成立时才能参与 veto；两个仅有中心点稳定的轨迹不能互相证明。

### 重复空白分隔走廊

- 对每个支持行，计算左字段右边界与右字段左边界之间的空白区间。
- 以所有支持行的区间求共同交集：

  ```text
  corridor_x0 = max(左字段右边界)
  corridor_x1 = min(右字段左边界)
  ```

- 只有 `corridor_x1 - corridor_x0` 大于同一 bbox 抖动容差时，才认为存在稳定列缝。
- 当前 span 对的间隙必须穿过该共同走廊；走廊不能只在单行存在。
- 走廊宽度按支持行的实际 bbox 计算，不使用独立的固定业务阈值。

### 保护条件

- 支持行少于 3 行：不 veto。
- 轨迹不稳定、字段包络交叉或走廊交集为空：不 veto。
- 两个片段属于同一字段的词内/中文碎片，且没有另一组稳定轨迹见证：不 veto。
- 换行字段、占位符、纯数字连续记录和来源不完整的 span：沿用现有规则，不因新几何判断改变行为。

## 数据流与调用位置

新判断位于 `src/hexai_pdf_parser/tables/wireless_structure/text_runs.py` 的 `build_text_runs()` 内，在同视觉行 group 即将通过 `_join_text()` 合成为 atom 之前：

```text
native spans
  -> 视觉行聚类
  -> 计算区域级对齐轨迹和空白走廊
  -> 现有 _can_join()
  -> alignment AND corridor veto
  -> atoms
  -> 列带、物理网格、逻辑网格
```

轨迹分析只读取当前函数已经拥有的 native span 字段及 bbox；不得在此阶段重新访问页面对象或调用 `page.get_text("words")`。建议将轨迹提取、走廊求交和 veto 判断拆为私有纯函数，便于单元测试并保持 `build_text_runs()` 的职责清晰。

第一版不新增跨模块诊断接口，避免扩大改动范围。单元测试通过私有纯函数返回值验证轨迹类型、支持行数和共同走廊；诊断结果不能成为后续结构恢复的输入依赖。

## 测试设计

### 正例

1. 构造 Page 960 风格的 5 列行：金额右边界稳定、文本左边界稳定，中间存在多行共同空白走廊；验证金额与文本不合并，后续列带仍能保持两列。
2. 覆盖普通数字 + 中文、千分位金额 + 中文两种实际 native span 组合形态。

### 反例

1. 只有 1～2 个支持行时不 veto。
2. 两个真实同字段碎片具有连续来源和相近间距，但没有第二组稳定对齐轨迹/共同走廊时仍合并。
3. 只有中心点接近、没有稳定左/右边界的居中文本不 veto。
4. 支持行的空白区间没有共同交集时不 veto。
5. 轨迹支持行中字段边界交叉或顺序不稳定时不 veto。

### 回归

- 在 `tests/test_wireless_structure_text_runs.py` 增加 veto 正反例，在 `tests/test_wireless_structure_recoverer.py` 增加 5 列恢复集成用例。
- 保留现有 `build_text_runs()` 的中文碎片、词内数字、金额、占位符、换行字段和输出顺序测试。
- 运行无线结构、列带、网格、表头跨度及表格提取相关测试，确认不引入 occupancy conflict。
- 增加 no-words 守卫，证明新逻辑不调用 `page.get_text("words")`。

## 页面级验收

使用 `fix/zh_all_table_pages.pdf` 页索引 `960`，在新的独立输出目录重跑。验收内容：

- 模型仍检测到上下两张表，区域不吸收标题、“续：”或说明正文。
- 两张表均恢复为 `wireless_span_recovery`，列数为视觉上的 5 列，金额与受限类型保持独立。
- 不再出现 `账面价值/受限类型`、金额/文本同槽位冲突。
- 所有逻辑槽位恰好由一个 Cell 占用，空槽位按既有规则逐格物化。
- 最终 PNG 的两张表边界、列线和换行文本归属正确，相邻正文未误并。
