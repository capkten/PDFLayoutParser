# PDFParser 实例级 PDF 句柄复用设计

## 背景

`PDFParser` 当前缓存的是解析模型 `self._document`，不缓存 PyMuPDF 的 `fitz.Document` 句柄。首次调用区域提取时，页面尺寸或元数据可能由 `Loader.load()` 单独打开 PDF 取得；实际区域读取随后再次 `fitz.open()`。图片和页面渲染 API 还会通过辅助类按页打开 PDF。`PDFParser.__exit__()` 当前为空实现。

对同一 PDF 连续发起多个区域/轻量提取请求时，打开和关闭文档的固定成本会重复发生，而请求本身只处理少量区域内容。

## 目标与范围

对一个以文件路径构造的 `PDFParser` 实例，首次需要 PDF 页面数据时懒打开一个 `fitz.Document`，并在该实例后续的区域与轻量 API 调用间复用。范围包括：

- 文本、表格、图片及页面分类提取。
- `extract_text_in_region`、`extract_table_in_region`、`extract_table_structure`、`extract_image_in_region`、`render_region`。
- `extract_images`、`render_pages` 和页面尺寸查询。

完整 `parse()` 流水线继续使用自己的句柄管理方式：顺序模式复用流水线内的一个句柄，线程模式由各 worker 管理各自的句柄。实例级句柄不传入流水线 worker。

以现成 `Document` 对象构造的 `PDFParser` 不持有 PDF 文件句柄，现有基于该对象的行为保持不变。

## 生命周期

- 增加实例级懒打开助手；未发生 PDF 读取时不打开文件。
- 增加幂等的 `close()`，关闭并清除实例持有的句柄。
- `__exit__()` 调用 `close()`，使 `with PDFParser(path)` 成为资源释放边界；`__enter__()` 不提前打开文件。
- 关闭后的实例再次执行需要 PDF 的轻量 API 时，按需重新打开句柄。这样显式关闭会立即释放资源，同时不破坏现有实例的可重用性。
- 同一个实例的轻量 API 按顺序使用句柄；不承诺同一实例被多个线程并发调用。完整解析流水线的 worker 生命周期不变。

## 代码结构

- `PDFParser` 负责句柄的惰性创建、持有和关闭。
- `Loader` 支持从调用方提供的已打开文档读取页数、页面尺寸、旋转角度和页面类型；由调用方提供时，`Loader` 不关闭该句柄。
- 解析器中的图片和渲染路径调用接受现有文档/页面的低层提取方法，避免逐页辅助入口重新打开同一路径。
- 现有 `ApiResult` 错误包装、坐标格式、过滤参数和输出路径语义保持不变。

## 验收条件

1. 在同一个路径型 `PDFParser` 实例中连续调用文本区域、表格区域等轻量 API 时，首次打开后不因每次 API 调用而再次打开同一文件。
2. `_get_page_sizes()` 与 `Loader` 元数据生成复用实例句柄，不另外打开 PDF。
3. `close()` 和上下文退出会关闭实例句柄；重复关闭安全，之后再次调用会按需重新打开。
4. 图片和渲染的多页调用复用同一个实例句柄，不再由逐页辅助调用重复打开文件。
5. `parse()` 及其并行 worker 的句柄管理不变。
6. 现有提取结果、错误返回和区域坐标行为不变。

## 测试策略

- 用临时 PDF 和 `fitz.open` 调用计数验证同一解析器实例跨不同轻量 API 只打开一次。
- 验证关闭和上下文退出确实释放句柄，并覆盖关闭后按需重开。
- 验证新建的另一个解析器实例拥有独立句柄。
- 运行相关 `PDFParser`、Loader、图片提取、渲染测试；完整测试结果与环境限制分开报告。

## 不做的事项

- 不改完整 `parse()` 流水线或 worker 数量/后端策略。
- 不在不同 `PDFParser` 实例间共享全局文档缓存。
- 不改变提取算法、区域识别、JSON/Markdown 输出结构或持久化格式。
