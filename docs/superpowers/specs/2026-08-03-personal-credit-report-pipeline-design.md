# 个人征信报告 Pipeline 设计

## 目标

提供一个面向个人征信报告的函数调用入口。该入口统一处理“本人版”和“本人简版”，复用主 pipeline 的页面处理和表格结构提取逻辑，同时为后续定制高精度的无线表格区域检测预留独立接口。

## 公开接口

```python
from hexai_pdf_parser.personal_credit_report import parse_personal_credit_report

document = parse_personal_credit_report(
    pdf_path,
    output_dir=output_dir,
    render_dpi=200,
    page_indices=None,
    debug=False,
    debug_pipeline=False,
)
```

该函数不要求调用方预先判断 PDF 是“本人版”还是“本人简版”，统一返回现有的 `Document` 模型，并保持当前 JSON、Markdown、图片和调试输出格式不变。

该函数是项目后续使用个人征信报告解析能力的正式入口。内部 pipeline 和 extractor 类不作为项目调用接口。

## 页面处理流程

所有页面使用同一条处理流程，不在入口处先区分报告版本：

1. 检测可信的有线表格区域。
2. 复用现有线解析逻辑提取有线表格结构，包括虚线合并、线段合并、跨行和跨列处理。
3. 将已确认的有线表格区域登记为文本排除区域。
4. 使用个人征信报告专用检测器检测无线表格候选区域。本阶段只确定接口，不实现该检测算法。
5. 复用现有 native span 和 legacy text-alignment 逻辑提取无线表格结构。
6. 合并并去重有线表格和无线表格，保留现有的 source、confidence、cell、span 等元数据。
7. 复用现有布局构建、渲染、页面输出、文档输出和调试输出逻辑。

有线表格区域是文本过滤的强逻辑依据。文本块中心点落入可信有线区域时，不得继续参与无线表格恢复。

## 组件边界

### `parse_personal_credit_report`

负责公开函数接口，并委托个人征信报告专用实现完成文档和页面处理。不得复制主 pipeline 的输出、并发、渲染和文件写入逻辑。

### 个人征信报告页面表格 extractor

负责页面内“先有线、后无线”的顺序和个人征信专用区域检测器接口。复用 `TableExtractor` 已有的有线解析、无线 span 恢复、legacy 文本对齐、单元格构造和表格规范化逻辑。

### 个人征信报告无线区域检测器

只负责个人征信报告的无线候选区域检测和验证。检测算法在本阶段暂不实现，先固定接口，待结合两个真实 PDF 的版式和调试结果确认规则后再实现。

## 本阶段明确不做的内容

- 不要求在处理前判断输入是本人版还是本人简版。
- 不改变默认主 `Pipeline` 的行为。
- 不实现或调优个人征信报告无线表格区域检测规则。
- 不使用 PyMuPDF 表格提取逻辑替换当前实现。
- 不复制现有页面输出或表格单元格构造算法。

## 后续实现验收标准

- 两种报告版本都可以通过同一个公开函数传入。
- 每个页面始终先执行有线阶段，再执行无线阶段。
- 有线区域内的文本不会进入无线候选区域。
- 现有表格结构提取逻辑被复用，而不是复制。
- 后续替换无线区域检测规则时，不需要改变公开函数签名。
- 现有主 pipeline 测试保持通过。
