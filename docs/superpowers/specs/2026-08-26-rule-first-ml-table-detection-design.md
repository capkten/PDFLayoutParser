# 规则初筛后模型精定位表格检测设计

## 目标

调整表格检测主流程：每页先使用现有规则尽量召回疑似表格页，只有命中的页面才调用模型进行精确表格定位，最终表格结果完全以模型结果为准。

## 已确认的行为

- 规则阶段是候选页筛选，不是最终表格结果。
- 规则阶段复用现有线框、斑马纹和文本对齐检测能力。
- 规则阶段以“尽量多检、不漏页”为目标；规则检测到任意候选表格即可触发模型。
- 模型在候选页上对整页进行精确定位。
- 只有模型返回并成功解析的表格进入最终 `page.tables`。
- 模型无结果、调用异常或模型框无法完成结构解析时，不保留规则阶段结果。
- 未被规则命中的页面不调用模型，也不产生表格结果。
- 不再通过 `use_ml` 区分规则模式和模型模式；模型是候选页命中后的固定阶段。
- 模型路径和置信度配置继续保留，用于指定模型和检测阈值。
- 相关代码注释、CLI 帮助文本和文档必须同步描述新流程，不能继续描述为“可选 ML 模式”或“ML 结果与规则结果合并”。

## 数据流

```text
单页
  -> 规则候选检测
  -> 无候选：page.tables = []
  -> 有候选：模型整页检测
       -> 无模型框/异常：page.tables = []
       -> 有模型框：按模型框执行表格结构解析
            -> 成功结果写入 page.tables
```

规则阶段产生的表格对象只用于判断候选页，不直接进入最终文档，也不参与最终表格可视化。

## 组件边界

- `TableExtractor` 继续作为单页表格检测入口。
- 现有规则提取逻辑整理为候选页检测阶段，返回候选表格或等价的命中信号。
- 模型检测逻辑负责候选页的精确外框定位。
- 现有无线表格/文本对齐结构处理逻辑接收模型框，并构造最终表格。
- 现有有线表格规则结果不再作为模型结果的补充结果写入最终文档。

## 兼容与错误处理

- 模型调用失败不降级到规则表格结果，最终该页表格为空。
- 非候选页不触发模型，避免无必要的模型推理。
- Markdown 和可视化输出沿用现有 Pipeline 输出路径。
- 本设计不扩展输出格式；JSON 输出是否移除属于后续独立调整，不在本次表格检测行为变更中处理。

## 测试要求

- 规则命中页面会调用模型，并且最终只使用模型产生的表格。
- 规则未命中页面不会调用模型，最终表格为空。
- 模型无结果或抛出异常时，规则候选结果不会泄漏到最终表格。
- 模型路径和置信度仍能传递到模型检测器。
- 现有表格结构解析、Pipeline 和 CLI 测试保持通过；涉及旧 `use_ml` 语义的测试和注释需要同步更新。
